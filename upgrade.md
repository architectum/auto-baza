# 🚀 АвтоБаза — План модернізації (upgrade.md)

> Структурований план покращень додатку з нумерацією для зручного вибору пунктів для реалізації.
> Формат посилання: `"реалізовуємо пункти: 2.13, 3.14.2, 4.1.3-8"`

---

## 1. Дизайн та візуальне оформлення

### 1.1. Редизайн кольорових схем

**Проблема:** Поточні кольорові схеми базові, палітра обмежена стандартними кольорами (синій, зелений, червоний, фіолетовий). Темна тема недостатньо контрастна.

**Користь:** Додаток виглядатиме сучаснішим та преміальнішим, зросте лояльність користувачів, зменшиться зорова втома при тривалому використанні.

1. **1.1.1.** Переробити HSL-палітру для кожної існуючої кольорової схеми, додавши більше проміжних відтінків (50, 100, 200, ..., 900) для гнучкості → Реалізація: створити design tokens через CSS custom properties у `index.css`, замінити хардкодовані значення кольорів у Tailwind-класах на змінні.
2. **1.1.2.** Додати 4-6 нових кольорових акцентів: Amber (бурштиновий), Teal (бірюзовий), Rose (трояндовий), Slate (сланцевий), Cyan (блакитний), Indigo (індіго) → Реалізація: розширити масив `ACCENT_COLORS` у `SettingsSheet.tsx`, додати відповідні CSS custom properties у `ThemeProvider.tsx`.
3. **1.1.3.** Покращити контрастність темної теми: збільшити різницю між фоном та текстом до WCAG AA стандарту (мінімум 4.5:1) → Реалізація: аудит всіх `--background`, `--foreground`, `--muted` змінних у `ThemeProvider.tsx`, корекція значень.
4. **1.1.4.** Додати AMOLED-темну тему (чисто чорний фон `#000000`) для OLED-екранів → Реалізація: новий варіант теми в `SettingsSheet.tsx` з `--background: 0 0% 0%`.
5. **1.1.5.** Уніфікувати кольори статусів (проблема/рішення/нотатка/пробіг) в єдину систему, яка працює консистентно в усіх темах → Реалізація: створити окремий набір CSS custom properties для статусних кольорів у `ThemeProvider.tsx`.

### 1.2. Типографіка

**Проблема:** Додаток використовує системний шрифт `system-ui`, що призводить до візуальної невідповідності між різними пристроями та операційними системами.

**Користь:** Єдиний, впізнаваний вигляд додатку на всіх пристроях, покращена читабельність, більш професійне враження.

1. **1.2.1.** Підключити Google Font Inter (або Roboto) як основний шрифт через `@font-face` з `font-display: swap` → Реалізація: додати `<link>` у `index.html`, оновити `font-family` в `index.css`. Файли шрифтів кешувати через PWA service worker.
2. **1.2.2.** Створити типографічну шкалу (type scale) з чіткими розмірами для заголовків, тексту, підписів → Реалізація: визначити CSS custom properties `--text-xs`, `--text-sm`, `--text-base`, `--text-lg`, `--text-xl` та використовувати їх замість довільних значень `text-[14px]`.
3. **1.2.3.** Додати моноширинний шрифт (JetBrains Mono / Fira Code) для відображення номерних знаків та цифрових значень → Реалізація: оновити `LicensePlate.tsx` та числові поля у `CarProfile.tsx`.

### 1.3. Іконки та графічні елементи

**Проблема:** Іконки (файл `Icons.tsx`, 11 КБ) — кастомні SVG, але не всі мають однаковий стильовий напрямок, частина з них візуально «важкі», не використовується stroke-width консистентно.

**Користь:** Візуальна гармонія всіх елементів інтерфейсу, професійніший вигляд, краще сприйняття на малих екранах.

1. **1.3.1.** Провести аудит всіх SVG-іконок в `Icons.tsx` і уніфікувати: однаковий `stroke-width` (1.5-2), однаковий viewBox (24×24), однаковий стиль (outline або filled) → Реалізація: перерисувати проблемні іконки вручну у `Icons.tsx`.
2. **1.3.2.** Додати іконки для відсутніх станів: порожній список, помилка завантаження, відсутній аватар → Реалізація: створити нові SVG-компоненти в `Icons.tsx`.
3. **1.3.3.** Створити анімовані мікро-іконки для індикації дій: завантаження (spinner), успіх (checkmark), помилка (shake) → Реалізація: CSS-анімації `@keyframes` в `index.css`, прив'язані до класів.
4. **1.3.4.** Додати favicon набір (16×16, 32×32, 180×180 apple-touch-icon, maskable icon для PWA) → Реалізація: генерація з основного логотипу, додавання в `public/`, оновлення `index.html` та `vite.config.ts` PWA конфігурації.

### 1.4. Елементи та компоненти UI

**Проблема:** Кнопки, інпути, картки мають різні стилі padding, border-radius, тіней. Немає єдиної дизайн-системи.

**Користь:** Консистентний вигляд всього додатку, швидша розробка нових фіч (перевикористання стилів), менше CSS-коду.

1. **1.4.1.** Створити базовий UI-kit з єдиними стилями для: Button (primary, secondary, ghost, danger), Input, Select, Textarea, Card, Badge, Modal → Реалізація: виділити загальні Tailwind-класи у утилітні CSS-класи або створити React-компоненти-обгортки у новій папці `src/components/ui/`.
2. **1.4.2.** Уніфікувати `border-radius`: визначити токени `--radius-sm: 6px`, `--radius-md: 12px`, `--radius-lg: 16px`, `--radius-full: 9999px` та використовувати тільки їх → Реалізація: CSS custom properties у `index.css`, рефакторинг Tailwind-класів.
3. **1.4.3.** Створити єдину систему тіней: `--shadow-sm`, `--shadow-md`, `--shadow-lg`, `--shadow-card` → Реалізація: CSS custom properties, заміна хардкодованих `shadow-*` класів.
4. **1.4.4.** Покращити дизайн елементів історії обслуговування: зробити іконку типу запису всередині рамки на повну ширину, уніфікувати тінь для підсвічування вибраного елемента → Реалізація: рефакторинг JSX та Tailwind-класів у `ServiceHistory.tsx`, створення єдиного стилю для всіх типів записів.
5. **1.4.5.** Редизайн карток авто у списку: чіткіше візуальне розділення інформаційних блоків, покращення читабельності тексту на фоні аватарки → Реалізація: рефакторинг `CarCard.tsx`, додати backdrop-blur або gradient overlay під текст.
6. **1.4.6.** Покращити дизайн порожніх станів (empty states): додати ілюстрації та дружній текст замість простого «немає даних» → Реалізація: SVG-ілюстрації в `Icons.tsx`, відображення у `CarList.tsx`, `ServiceHistory.tsx`, `Statistics.tsx`.
7. **1.4.7.** Редизайн форми додавання авто (`CarForm.tsx`): розбити на візуальні секції з заголовками, додати прогрес-бар заповнення форми → Реалізація: рефакторинг JSX-структури, додавання секційних заголовків.

## 2. UX-покращення (досвід використання)

### 2.1. Навігація та потоки

**Проблема:** Додаток не має router — навігація реалізована через стани в `App.tsx` (`page` state), що ускладнює використання кнопки «Назад» браузера та deep linking.

**Користь:** Користувач може використовувати системну кнопку «Назад», ділитися посиланнями на конкретні сторінки, повернутися на ту ж сторінку після перезавантаження.

1. **2.1.1.** Інтегрувати `react-router-dom` для маршрутизації замість ручного управління станом `page` → Реалізація: встановити бібліотеку, створити `Router` у `App.tsx`, замінити `setPage()` на `navigate()`. Маршрути: `/` (список), `/car/:id` (профіль), `/car/new` (форма), `/stats` (статистика), `/settings` (налаштування).
2. **2.1.2.** Додати підтримку апаратної кнопки «Назад» (History API) для коректної навігації → Реалізація: автоматично працюватиме після інтеграції react-router.
3. **2.1.3.** Зберігати позицію скролу при поверненні назад зі сторінки авто до списку → Реалізація: `ScrollRestoration` компонент з react-router або ручне збереження через `sessionStorage`.
4. **2.1.4.** Додати breadcrumbs або заголовок поточної секції на внутрішніх сторінках → Реалізація: компонент `Header` з динамічним заголовком на основі поточного маршруту.

### 2.2. Пошук та фільтрація

**Проблема:** Пошук працює тільки по номеру, імені та телефону. Немає фільтрації та сортування.

**Користь:** Автомайстер швидше знаходить потрібне авто серед великого списку, може групувати авто за різними критеріями.

1. **2.2.1.** Розширити пошук: додати пошук по марці, моделі, кольору авто → Реалізація: оновити функцію фільтрації у `CarList.tsx` для перевірки додаткових полів.
2. **2.2.2.** Додати фільтри: «Тільки з незакритими проблемами», «Тільки без аватарки», «За маркою» → Реалізація: стан фільтрів у `CarList.tsx`, UI-панель фільтрів (випадаюча або бічна).
3. **2.2.3.** Додати сортування списку авто: за датою останнього візиту, за кількістю проблем, за абеткою (ім'я клієнта) → Реалізація: dropdown сортування у `CarList.tsx`, функція компаратора.
4. **2.2.4.** Реалізувати debounce для пошуку (300мс) для уникнення зайвих перерендерів → Реалізація: `useDebounce` хук або `setTimeout` у `CarList.tsx`.
5. **2.2.5.** Додати пошук по записах історії обслуговування всередині профілю авто → Реалізація: пошуковий рядок у `ServiceHistory.tsx` з фільтрацією записів по тексту.

### 2.3. Форми та введення даних

**Проблема:** Форми великі, без валідації, без індикації обов'язкових полів, без зворотного зв'язку при помилках.

**Користь:** Менше помилок при введенні, швидше заповнення форм, менше «зависань» з незрозумілими помилками.

1. **2.3.1.** Додати валідацію полів у реальному часі у `CarForm.tsx`: обов'язкові поля (номер або ім'я клієнта), формат телефону, мінімальні/максимальні значення року → Реалізація: стан помилок для кожного поля, відображення повідомлень під полями, блокування кнопки «Зберегти» до виправлення.
2. **2.3.2.** Додати зірочки (*) біля обов'язкових полів у формах → Реалізація: CSS-стиль + JSX модифікація лейблів.
3. **2.3.3.** Реалізувати автозбереження чернетки форми створення авто в `localStorage` → Реалізація: `useEffect` з `debounce` для збереження стану форми, відновлення при повторному відкритті.
4. **2.3.4.** Додати підтвердження виходу з незбереженої форми (beforeunload + програмне) → Реалізація: `window.addEventListener('beforeunload')`, та програмна перевірка при натисканні «Назад».
5. **2.3.5.** Покращити введення номерного знаку: автоматична капіталізація, формат-маска → Реалізація: `toUpperCase()` на onChange, регулярний вираз для формату.
6. **2.3.6.** Додати автокомпліт для марки/моделі авто з предзавантаженого списку популярних марок → Реалізація: масив марок/моделей, компонент Combobox з фільтрацією.

### 2.4. Зворотній зв'язок та стани

**Проблема:** Немає системи тост-сповіщень, помилки часто виводяться через `alert()` або `console.error()`, відсутні стани завантаження для деяких операцій.

**Користь:** Користувач завжди знає що відбувається, менше розгублення, краще сприйняття швидкості роботи.

1. **2.4.1.** Створити систему Toast-сповіщень (success, error, info, warning) → Реалізація: компонент `Toast.tsx` з контекстом `ToastProvider`, зберігати чергу сповіщень у стані, автоматичне зникнення через 3-5 секунд, позиціювання внизу екрана.
2. **2.4.2.** Замінити всі `alert()` виклики на Toast-сповіщення → Реалізація: знайти всі `alert()` у кодовій базі (є у `CarForm.tsx`, `CarProfile.tsx`, `ServiceHistory.tsx`, `TextHistoryInput.tsx`), замінити на `toast.success()` / `toast.error()`.
3. **2.4.3.** Додати скелетон-завантаження (skeleton loaders) для списку авто та профілю → Реалізація: компоненти `CarCardSkeleton`, `CarProfileSkeleton` з CSS-анімацією пульсації.
4. **2.4.4.** Додати pull-to-refresh жест для оновлення списку авто → Реалізація: компонент `PullToRefresh` з touch-обробниками, виклик `fetchCars()` при відпусканні.
5. **2.4.5.** Показувати індикатор прогресу при завантаженні/збереженні фото → Реалізація: `onUploadProgress` callback у `storage.ts`, progress bar у компонентах.
6. **2.4.6.** Додати Haptic Feedback (вібрацію) при критичних діях на мобільних пристроях → Реалізація: `navigator.vibrate(50)` при видаленні, збереженні, помилці.

### 2.5. Жести та мобільна взаємодія

**Проблема:** Додаток орієнтований на мобільне використання (PWA), але не використовує мобільні жести (свайпи, тощо).

**Користь:** Більш нативне відчуття додатку, швидша навігація, менше натискань для частих дій.

1. **2.5.1.** Додати swipe-to-delete для записів історії обслуговування → Реалізація: touch-обробники на елементах `ServiceHistory.tsx`, анімація зсуву, кнопка видалення що з'являється.
2. **2.5.2.** Додати свайп назад для навігації між сторінками → Реалізація: edge-swipe gesture handler в `App.tsx`, що імітує натискання «Назад».
3. **2.5.3.** Додати long-press (довге натискання) на картці авто для швидких дій (виклик клієнта, видалення) → Реалізація: `onTouchStart` / `onTouchEnd` з таймером 500мс, контекстне меню.
4. **2.5.4.** Реалізувати кнопку «Зателефонувати клієнту» (tel: link) безпосередньо на картці авто → Реалізація: `<a href="tel:+380...">` іконка телефону на `CarCard.tsx`.

### 2.6. Офлайн-режим та PWA

**Проблема:** PWA налаштовано, але офлайн-режим не реалізовано повноцінно — дані завантажуються тільки з Firestore.

**Користь:** Автомайстер може переглядати список авто та історію без інтернету (у гаражі, на виїзді), дані синхронізуються при відновленні з'єднання.

1. **2.6.1.** Увімкнути Firestore offline persistence → Реалізація: `enableIndexedDbPersistence(db)` у `firebase.ts`.
2. **2.6.2.** Додати індикатор стану з'єднання (online/offline) → Реалізація: `useOnlineStatus()` хук з `navigator.onLine`, іконка в хедері.
3. **2.6.3.** Кешувати зображення аватарів через Service Worker → Реалізація: оновити конфігурацію `vite-plugin-pwa` у `vite.config.ts`, додати runtime caching strategy для Firebase Storage URL.
4. **2.6.4.** Реалізувати чергу дій (action queue) для офлайн-мутацій → Реалізація: зберігати незбережені зміни у IndexedDB, синхронізувати при відновленні з'єднання.

## 3. Функціональні покращення

### 3.1. Управління клієнтами

**Проблема:** Дані клієнта (ім'я, телефон) зберігаються всередині запису авто. Якщо у клієнта кілька авто — його дані дублюються і не пов'язані.

**Користь:** Один клієнт — кілька авто, зміна контактів в одному місці, можливість бачити повну історію клієнта по всіх його авто.

1. **3.1.1.** Створити окрему колекцію `clients` у Firestore з полями: ім'я, телефон, email, нотатки → Реалізація: нова колекція, оновлення `types.ts`, міграція існуючих даних.
2. **3.1.2.** Зв'язати авто з клієнтом через `clientId` замість інлайн-полів → Реалізація: додати поле `clientId` до Car, оновити `CarForm.tsx` з автокомплітом по існуючих клієнтах.
3. **3.1.3.** Сторінка клієнта з переліком всіх його авто та загальною статистикою → Реалізація: новий компонент `ClientProfile.tsx`, новий маршрут `/client/:id`.
4. **3.1.4.** Швидкий виклик або SMS клієнту з його профілю → Реалізація: `tel:` та `sms:` посилання в UI.

### 3.2. Розширена статистика

**Проблема:** Модуль статистики (`Statistics.tsx`, 133 КБ!) — монолітний і дуже великий. Додавання нових графіків ускладнене.

**Користь:** Можливість додавати нові статистики без ризику зламати існуючі, краща продуктивність (lazy loading графіків).

1. **3.2.1.** Розбити `Statistics.tsx` на окремі компоненти по графіках → Реалізація: виділити кожен графік у окремий файл: `charts/RateChart.tsx`, `charts/CostTimeChart.tsx`, `charts/HeatmapChart.tsx` тощо.

## 4. Архітектурні покращення

2. **4.8.2.** Аудит Storage Rules → Реалізація: обмежити розмір файлів (наприклад, 10 МБ), дозволити тільки певні content-types (image/*, application/pdf).
3. **4.8.3.** Перенести AI-виклики на Cloud Functions замість Vite proxy → Реалізація: Cloud Function як API endpoint для Gemini, видалити прямий доступ до API ключа з client-side.

5. **4.8.5.** Реалізувати автоматичний логаут при неактивності (15 хвилин) → Реалізація: таймер inactivity у `AuthLayer.tsx`, подія на рух миші / touch для скидання.
