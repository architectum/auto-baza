# 📋 План покращень додатку АвтоБаза (next-ver.md)

Цей документ містить детально структурований список пропозицій щодо покращення зовнішнього вигляду (UI), зручності користування (UX), функціональних можливостей та технічної архітектури веб-додатка **АвтоБаза**.

Кожен пункт має унікальну нумерацію (наприклад, `1.2.1`, `2.4.12`, `3.6.1`), що дозволяє легко посилатися на окремі завдання або цілі розділи під час постановки задач розробки.

---

## 1. Зовнішній вигляд та UI (Visual Design & User Interface)

### 1.1. Дизайн-система, теми та колірна гама
1.1.1. **Оптимізація контрастності в темній темі:** Допрацювати колірні токени CSS (`--t-surface-card`, `--t-text-muted`, `--t-surface-input`) для забезпечення відповідності стандарту WCAG 2.1 AA (контрастність не менше 4.5:1).
1.1.2. **Розширення палітри акцентних кольорів:** Додати нові пресети тем (наприклад, "Нічний смарагд", "Неоновий кіберпанк", "Сучасний титан", "Захід сонця") у `ThemeProvider.tsx`.
1.1.3. **Покращення Glassmorphism-ефектів:** Врегулювати значення `backdrop-filter` та прозорості у фіксованій шапці (Header) та модальних вікнах, щоб запобігти розмиттю та покращити читабельність тексту при прокрутці.
1.1.4. **Гнучке налаштування номерних знаків:** Розширити компонент `LicensePlate.tsx` — додати підтримку єврономерів (синя смуга з прапором ЄС), американських квадратних номерів, транзитних (червоних) та електромобільних (зелені літери).
1.1.5. **Колірний ідентифікатор авто:** Додати візуальний колірний маркер (кольорова крапка або смужка реального кольору кузова) на картці авто у списку.

### 1.2. Компоненти та типографіка
1.2.1. **Уніфікована система шрифтів:** Підключити сучасний шрифт (Inter / Plus Jakarta Sans) через Google Fonts для покращення читабельності чисел, пробігу та номерів телефонів.
1.2.2. **Покращені картки автомобілів у списку:** Рефакторинг `CarList.tsx` — переробка бекграунд-аватарів авто (зменшення прозорості з 0.45 до гармонійного градієнтного накладання) та додавання компактного віджету зі статусом останнього ТО.
1.2.3. **Оновлені значки статусів (Badges):** Редизайн індикацій відкритих проблем, вирішених робіт та нагадувань з додаванням чітких ікон та контрастних фонів.
1.2.4. **Інтерактивна схема зв'язку «Проблема - Рішення»:** Оновлення `LinkLines.tsx` для наочнішого візуального зв'язку між записами історії ремонту (кольорові з'єднувальні лінії із можливістю підсвічування при наведенні або тапі).
1.2.5. **Оновлені порожні стани (Empty States):** Додати ілюстрації або векторні іконки з швидкими діями ("Створити перше авто", "Завантажити демо-дані для ознайомлення") у компонент `EmptyState.tsx`.

### 1.3. Анімації, мікроінтеракції та візуальний відгук
1.3.1. **Плавні переходи при навігації (Transitions):** Додати View Transitions API або плавну анімацію перехода між списком авто `CarList`, профілем `CarProfile` та статистикою `Statistics`.
1.3.2. **Інтерактивність FAB-кнопки:** Додати мікроанімацію обертання/пульсації плаваючої кнопки додавання авто (`+`) при скролі сторінки.
1.3.3. **Анімовані скелетони завантаження:** Оновити `CarCardSkeleton` та `CarProfileSkeleton` з ефектом shimmer (мерехтіння градієнта).
1.3.4. **Оновлення зворотного зв'язку тостів (Toasts):** Додати анімований прогрес-бар для сповіщень (Toast) та підтримку дій "Скасувати" (Undo) для видалених записів.

### 1.4. Адаптивність та розмітка (Responsive & Layout)
1.4.1. **Оптимізація для планшетів та десктопів:** Реалізувати двоколонковий режим для екранів шириною від 768px (ліворуч — список авто з пошуком, праворуч — детальна картка обраного авто та історія).
1.4.2. **Safe Area Insets для iOS / Android:** Поліпшити підтримку вирізів екрана (Notch, Dynamic Island) та нижньої навігаційної смуги смартфонів через `env(safe-area-inset-bottom)`.
1.4.3. **Компактний щільний режим (Compact View):** Перемикач режиму відображення списку авто у верхній панелі (плитка / компактна таблиця).
1.4.4. **Підтримка поекранного горизонтального свайпу:** Навігація свайпом вліво/вправо між вкладками "Загальне", "Історія", "Файли/Діагностика", "Нагадування".

## 2. UX та Зручність користування (User Experience & Usability)

### 2.1. Оптимізація форм та введення даних
2.1.1. **Автоматична маска для номера телефону:** Інтегрувати інпут-маску `+380 (XX) XXX-XX-XX` з автоматичним форматуванням при введенні та валідацією українських операторів.
2.1.2. **Автокапіталізація номерних знаків:** Автоматичне переведення букв у верхній регістр (Upper Case) та видалення некоректних символів/пробілів під час введення держномера.
2.1.3. **Автозаповнення марки та моделі:** Інтегрувати список популярних авто в Україні (з автодоповненням / autocomplete) при введенні перших літер марки або моделі.
2.1.4. **Швидкі пресети пробігу:** При редагуванні пробігу показувати кнопки швидкої зміни: `+500 км`, `+1 000 км`, `+5 000 км`, `+10 000 км` для швидкої фіксації пробігу.
2.1.5. **Підказки валідації в реальному часі:** Показувати попередження, якщо пробіг вводиться менший за попередній збережений запис.

### 2.2. Навігація, пошук та фільтрація
2.2.1. **Розширені фільтри у списку авто:** Фільтрація за критеріями: "Є відкриті проблеми", "Потребує ТО", "Сортування за останнім візитом", "Сортування за маркою", "За роком випуску".
2.2.2. **Збереження стану пошуку та прокрутки:** Пам'ятати останній пошуковий запит та позицію скролу при поверненні із картки авто до списку.
2.2.3. **Швидкі дії на картці авто (Quick Actions):** Додати кнопочки швидкого зв'язку прямо з картки авто у списку: "Зателефонувати", "Написати у Viber", "Написати у Telegram".
2.2.4. **Глобальний швидкий пошук (Cmd+K / Ctrl+K):** Модальне вікно швидкого пошуку по всій автобазі з будь-якого екрана додатку через гарячі клавіші.

### 2.3. Юзабіліті історії обслуговування
2.3.1. **Швидкі теги робіт (Quick Service Tags):** Панель популярних категорій робіт над полем введення історії ("Заміна масла", "Діагностика підвіски", "Заміна колодок", "Шиномонтаж", "Заправка кондиціонера") для внесення запису в один тап.
2.3.2. **Групування історії за роками та місяцями:** Згортання/розгортання хронологічних блоків історії обслуговування для автомобілів із великою кількістю ремонтів.
2.3.3. **Зручне зв'язування проблеми та рішення:** Спрощена процедура з'єднання відкритих проблем із виконаним рішенням через перетягування (Drag-and-Drop) або швидку кнопку "Помітити як виконано".
2.3.4. **Попередній перегляд фотографій та документів:** Швидкий слайдер/галерея фотографій робіт із можливістю зумування (Pinch-to-zoom) та повороту зображень.

### 2.4. Мобільний та PWA досвід (Mobile & Offline UX)
2.4.1. **Pull-to-Refresh:** Жест потягнути донизу для примусового оновлення даних із Firestore на мобільних пристроях.
2.4.2. **Свайп-дії на картках (Swipe Actions):** Свайп картки авто або запису історії вліво — видалити, вправо — редагувати / зателефонувати.
2.4.3. **Тактильний відгук (Haptic Feedback):** Вібраційний відгук смартфона при успішно збереженій дії, скануванні голосом або видаленні запису.
2.4.4. **Індикатор стану офлайн-черги:** Показувати badge із кількістю несинхронізованих офлайн-записів та можливістю вручну запустити синхронізацію.
2.4.5. **Промпт встановлення PWA (Custom Install Banner):** Зручний власний банер з інструкцією для iOS Safari та Android Chrome щодо додавання АвтоБази на головний екран.
2.4.6. **Збереження чернеток при збої з'єднання:** Локальне збереження тексту незавершеного запису ремонту у LocalStorage у разі виклику або закриття браузера.
2.4.7. **Підтримка Dark Mode системи за замовчуванням:** Автоматичне визначення системної теми користувача при першому вході.
2.4.8. **Захист від випадкового закриття форми:** Попередження про незбережені зміни при спробі натиснути "Назад" під час редагування авто.
2.4.9. **Оптимізована сенсорна область (Touch Targets):** Збільшення розміру всіх активних кнопок та іконок до мінімуму 48х48px для зручної роботи в рукавичках або на СТО.
2.4.10. **Швидкий перехід у картах/навігаторі:** Кнопка відкриття геопозиції або адреси клієнта у Google Maps / Waze / Apple Maps.
2.4.11. **Підтримка сканування штрихкодів та QR:** Використання камери для зчитування QR-коду авто або штрихкоду запчастин (Web Code Detection API).
2.4.12. **Контекстне меню довгого тапу (Long Press):** Довгий тап по картці авто викликає меню швидких дій ("Копіювати VIN", "Поділитися карткою", "Додати проблему").
2.4.13. **Оптимізоване керування клавіатурою на мобільних:** Автоматичний скрол екрана до активного поля інпуту при відкритті віртуальної клавіатури, щоб вона не перекривала кнопки збереження.
2.4.14. **Нативне меню поширення (Web Share API):** Кнопка "Поділитися" для відправки деталей ремонту або кошторису через месенджери на мобільному пристрої.
2.4.15. **Автоматичне очищення кешу зображень:** Фонове очищення застарілих тимчасових фотографій для економії місця на пристрої.
2.4.16. **Зручний календарний пикер для нагадувань:** Мобільний повноекранний календар із вибором дати наступного візиту або заміни масла.

## 3. Нові функціональні можливості (Business Logic & Features)

### 3.1. Управління автомобілем та VIN-коди
3.1.1. **Підтримка VIN-коду:** Додати поле `vin` у модель `Car` (17-значний VIN номер) із валідацією контрольної суми.
3.1.2. **Сканер VIN-коду камери:** Розпізнавання VIN-коду з фото шильдика на кузові або під лобовим склом.
3.1.3. **Автоматична розшифровка VIN:** Автозаповнення характеристик авто (марка, модель, рік, тип двигуна, об'єм, тип палива, привід, коробка передач) через інтеграцію з VIN API.
3.1.4. **Історія власників та державна реєстрація:** Можливість додавати нотатки про зміну держномера або власника автомобіля.

### 3.2. Модуль запчастин та матеріалів (Parts & Inventory)
3.2.1. **Каталог запчастин у записі рішення:** Можливість додавати списком запчастини до кожної виконаної роботи (`solution`).
3.2.2. **Детальні поля запчастини:** Назва, каталожний номер (артикул / OEM), кількість, ціна закупівлі, ціна для клієнта, постачальник.
3.2.3. **Статуси запчастин:** Позначки для кожної запчастини: "Замовлено", "В наявності", "Встановлено", "Повернено".
3.2.4. **Роздільний розрахунок фінансів:** Окремий підрахунок вартості робіт (людино-години) та вартості запчастин із розрахунком чистого прибутку (маржі).

### 3.3. Календар ТО, нагадування та CRM для клієнтів
3.3.1. **Модуль планового ТО:** Розрахунок дати/пробігу наступного технічного обслуговування (наприклад, кожні 10 000 км або 365 днів для заміни масла/фільтрів).
3.3.2. **Автоматичні сповіщення клієнтам:** Нагадування клієнту про необхідність проходження ТО або сезонної заміни шин через SMS / Viber / Telegram API.
3.3.3. **Календар завантаженості СТО:** Вкладка календаря з відображенням запланованих візитів авто по днях та годинах.
3.3.4. **Профіль клієнта (CRM):** Згрупований перегляд усіх автомобілів одного клієнта за номером телефону, загальна сума витрат клієнта та його персональна знижка.

### 3.4. Документообіг та Друковані Форми (Invoices & PDFs)
3.4.1. **Акт виконаних робіт (PDF):** Формування та завантаження офіційного Акта виконаних робіт із логотипом СТО, реквізитами, переліком робіт, запчастин, гарантійними зобов'язаннями та лініями для підписів.
3.4.2. **Рахунок-фактура / Кошторис:** Можливість згенерувати та відправити клієнту попередній кошторис ремонту перед початком робіт.
3.4.3. **Акт прийому-передачі автомобіля:** Фіксація стану авто при прийомі на СТО (наявні пошкодження, рівень палива, комплектація, особисті речі).
3.4.4. **Експорт сервісної книжки:** Завантаження повної історії обслуговування авто у форматі красивого PDF для клієнта при продажу автомобіля.

### 3.5. Публічний кабінет клієнта (Client Portal)
3.5.1. **Генерація публічного посилання:** Можливість створити унікальне захищене посилання на сервісну книжку конкретного авто.
3.5.2. **Відстеження статусу ремонту в реальному часі:** Клієнт може відкрити посилання на своєму смартфоні та бачити покроковий статус: "Прийнято", "В діагностиці", "Замовлення запчастин", "В роботі", "Готово до видачі".
3.5.3. **Фотозвіт для клієнта:** Можливість прикріплювати фото зношених/замінених запчастин, які клієнт бачить у своєму публічному кабінеті.

### 3.6. Штучний інтелект та мультимодальність (AI & GenAI)
3.6.1. **AI-сканер Техпаспорта:** Фотографічний сканер свідоцтва про реєстрацію ТЗ (техпаспорта) — автоматичне розпізнавання держномера, VIN, марки, модели, року та ПІБ власника з фото документа.
3.6.2. **AI-розпізнавання накладних та чеків запчастин:** Фото чека з автомагазину → AI автоматично витягує перелік запчастин, артикули та ціни і додає їх у поточний ремонт.
3.6.3. **AI Діагностичний консультант (DTC Reader):** Введення коду помилки (DTC, наприклад P0300, P0171) або симптомів робить запит до Gemini AI, який видає ймовірні причини несправності та покроковий чек-лист перевірки для майстра.
3.6.4. **Голосове підсумовування дня:** AI-асистент може прослухати голосовий звіт майстра в кінці дня та автоматично рознести виконані роботи по відповідних автомобілях.

### 3.7. Розширення модуля статистики та аналітики
3.7.1. **Фільтр за довільний період:** Можливість обирати точний діапазон дат "З [дата] по [дата]" у панелі статистики.
3.7.2. **Порівняльний аналіз періодів:** Порівняння доходів, кількості робіт та середнього чека (цей місяць vs минулий місяць, цей рік vs минулий рік).
3.7.3. **Аналіз прибутковості робіт vs запчастин:** Графік співвідношення заробітку на послугах та маржі на запчастинах.
3.7.4. **Аналітика повернень та повторних візитів:** Показник середнього інтервалу між візитами клієнтів та відсоток утримання (Retention Rate).
3.7.5. **Експорт аналітики в Excel / CSV:** Завантаження сирих даних статистики для подальшої обробки у бухгалтерії.

### 3.8. Командна робота та мульти-майстер (Multi-mechanic СТО)
3.8.1. **Профілі працівників СТО:** Підтримка декількох майстрів у межах одного акаунта СТО.
3.8.2. **Рольова модель (Permissions):** Ролі: "Адміністратор/Власник", "Приймальник", "Майстер", "Бухгалтер".
3.8.3. **Призначення відповідального майстра:** Закріплення конкретного майстра за кожною виконаною роботою або автомобілем.
3.8.4. **Розрахунок зарплати майстрів:** Статистика виробітку та доходу по кожному майстру за обраний період.

## 4. Технічні, продуктивні та інфраструктурні покращення

### 4.1. Оптимізація продуктивності та кешування
4.1.1. **Віртуалізація списків (Virtual Scroll):** Інтеграція `@tanstack/react-virtual` для списку автомобілів та історії робіт при великій кількості записів (понад 100 авто).
4.1.2. **Компресія зображень на клієнті:** Автоматичне зменшення роздільної здатності та стиснення фотографій у формат WebP перед завантаженням у Firebase Storage (економія до 80% трафіку).
4.1.3. **Кешування запитів Firestore:** Налаштування локального persistent cache для прискорення завантаження додатку в офлайн-режимі.
4.1.4. **Оптимізація розміру бандлу:** Динамічний `import()` та lazy loading для важких бібліотек (`jspdf`, `motion`, `@google/genai`).

### 4.2. Безпека, резервне копіювання та збереження даних
4.2.1. **Резервне копіювання (Backup & Restore):** Функція повного експорту всієї бази даних (авто, історія, налаштування) у файл JSON з можливістю відновлення.
4.2.2. **Аудит правил безпеки Firestore:** Регулярний аудит `firestore.rules` на відповідність принципам найменших привілеїв та перевірки прав власника.
4.2.3. **Автоматичне логування помилок:** Інтеграція клієнтського логування помилок у Firestore/Sentry для швидкого виявлення збоїв у розпізнаванні голосу або фото.
